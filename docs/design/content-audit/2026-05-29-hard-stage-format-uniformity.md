#### 유저 플로우 (9개 항목)

1. **노출 시점·트리거**  
   플레이어가 FirstScene의 스테이지 선택 UI(UIStageSelect)에서 Hard 탭을 선택한 뒤 진입할 때 노출된다. Hard 스테이지는 노멀 스테이지 일정 수 클리어 후 해금되므로, 노멀 전체를 완주한 고숙련 플레이어층이 주 대상이다. 현재는 Hard 그룹 100001부터 100010까지 아무런 시각적 포맷 변화가 없어 각 그룹 진입 시 "이전과 동일한 게임"으로 인식된다.

2. **화면 변화**  
   다양화 적용 시, UIStageSelect에서 Hard 그룹 100006 이후 스테이지에는 보드 크기 아이콘(예: 6×6, 7×7)이나 이동 횟수 제한 배지가 표시되어 현재 그룹과 이전 그룹이 시각적으로 구별된다. GPGameScene 진입 직후 보드가 9×9보다 작거나 이동 카운터가 UI에 노출되어 플레이어가 즉시 조건 변화를 인지한다.

3. **입력 행동**  
   플레이어는 더 작은 보드(예: 6×6 또는 7×7)에서 블록을 드래그하거나, moveCount 제한이 붙은 스테이지에서 이동 횟수를 의식하며 수를 아껴 매치를 계획한다. 이동 제한 스테이지에서는 현재 이동 소모가 빠른 즉흥 플레이 대신 계획적 매치 순서를 모색하게 된다.

4. **시스템 반응**  
   GPBoard가 boardSize에 따라 그리드 크기를 동적으로 설정하므로, `Stage.json`의 `boardSize` 값만 변경해도 엔진 변경 없이 6×6~9×9 보드가 생성된다. moveCount 변경도 GPGameScene의 이동 카운터 UI와 연동되어 있어 JSON 수정만으로 반영된다. 이동 횟수 소진 시 EFailReason.MoveOver로 처리되어 UIGameEnd에 실패 사유가 표시된다.

5. **반복·재발생 패턴**  
   Hard 스테이지는 반복 클리어가 가능하므로(Data.Login.hardStage는 최고 클리어 스테이지 추적), 플레이어는 점수 최적화를 위해 같은 스테이지를 여러 번 플레이한다. boardSize나 moveCount가 바뀐 스테이지에서는 매 시도마다 다른 전략이 유효하므로 재도전 동기가 높아진다.

6. **종료·해소 조건**  
   스테이지 targetScore 달성 시 GameClear(EGameState.GameClear)로 전환되고 UIGameEnd가 표시된다. moveCount 소진 시 EFailReason.MoveOver로 실패 처리된다. 클리어 후 Data.Login.hardStage가 갱신되며 다음 Hard 스테이지가 해금된다. 현재 Hard 스테이지는 time·moveCount가 무제한(-1)이므로 실패 조건이 사실상 없는 상태이나, 다양화 적용 후 moveCount 제한 스테이지에서는 실패 경로가 추가된다.

7. **다른 시스템과 상호작용**  
   일일 미션 중 NormalStageClear(EDailyCounter=1) 카운터는 노멀 스테이지에 한정되어 Hard 스테이지 클리어는 집계 대상이 아니다. 따라서 Hard 스테이지 다양화가 일일 미션 밸런스에 영향을 주지 않는다. 아이템 사용(addMoveItemCount, addTimeItemCount)은 Hard 스테이지에서도 동작하며, moveCount 제한 Hard 스테이지가 추가되면 AddMove 아이템 수요가 늘어 Shop tapIndex 2 아이템 사용률에 긍정적 영향을 줄 수 있다.

8. **엣지 케이스**  
   boardSize 6×6 스테이지를 추가하면 StageBlock.json의 해당 스테이지 보드 레이아웃을 6×6 범위 내로 새로 설계해야 한다. CatBox/WallCreator/PotalCreator 등 특수 블록을 6×6 보드에 배치할 경우, 블록 밀도가 높아져 연쇄 폭발이 과도하게 발생할 수 있으므로 초기 배치 밀도를 낮게 조정해야 한다. 또한 moveCount가 매우 낮은 스테이지(예: moveCount=5)에서 RainbowPang(52) 같은 와일드카드 블록이 초기 배치되면 과도하게 유리해질 수 있어 StageBlock 설계 시 주의가 필요하다.

9. **유저 정보·피드백**  
   Hard 스테이지 클리어 시 UIGameEnd에서 점수와 함께 이동 횟수 잔여분을 표시하면 플레이 효율에 대한 즉각적 피드백이 가능하다. 보드 크기 변화는 첫 진입 시 짧은 튜토리얼 메시지(Guide.json 또는 Tutorial.json 연동) 또는 UIAlarm 팝업으로 안내해 혼란을 방지할 수 있다. 장기적으로 Hard 스테이지별 최소 이동 클리어 수(최적 클리어) 기록을 Data.Stage.boomAllCount 확장 필드에 저장해 소셜 랭킹(UIRank)에 반영하면 경쟁 요소로 활용 가능하다.
